## Goal
- 가족이 등록된 진진거의 가짜를 추리하고 한 줄 이유를 남긴 뒤, 결과 공개 시점에 정답·풀이자별 결과·AI 자동 코멘트를 함께 본다.

## In scope
- 풀이 진입(`/quiz/:id/play`) — 옵션 카드 3장 셔플 표시.
- 풀이 제출 — 옵션 1개 선택 + 한 줄 이유(선택 입력).
- 결과 공개 동선(`/quiz/:id/result`) — 정답, 풀이자별 선택, 정답률, 속임률, AI 자동 코멘트.
- AI 자동 코멘트 1건 / 진진거 1건.
- "결과 보러 가기" 동선(자동 reveal 후 가족 첫 진입 시).
- 결과 화면에서 "남의 집 진진거에 공유하기" 진입 버튼(F7으로 핸드오프).

## Out of scope
- 가족 댓글(F6 spec).
- 랭킹 누적/주간 리셋(F6 spec).
- 게시판 공유 본문(F7 spec).
- 알림.

## User story
- As a 풀이자
- I want 가족이 올린 진진거에서 가짜를 추리하고 결과로 누가 맞혔는지 보고 싶다
- so that 우리 가족이 서로의 하루를 얼마나 알고 있는지 확인하며 웃을 수 있다.

## Definitions
- **셔플 시드(Shuffle seed)**: 옵션 표시 순서를 위한 결정적 셔플 값. 풀이자별로 다르게 부여하지만, 같은 풀이자에게는 항상 동일 순서로 보인다(중간에 새로고침해도 헷갈리지 않게).
- **선택 이유(Reason)**: 풀이자가 옵션을 고른 이유를 적는 1~80자 텍스트. 선택 입력.
- **정답률(Accuracy)**: 풀이자 N명 중 가짜를 맞힌 비율. 결과 공개 시점에 산출.
- **속임률(Fool rate)**: 가짜를 맞히지 못한 풀이자의 비율 = 1 − 정답률. PRD §16 정의.
- **AI 자동 코멘트**: 결과 공개 직후 시스템이 LLM을 호출해 만드는 결과 요약/해설 1건.

## Scenarios

```gherkin
Feature: 풀이 진입과 제출

  Scenario: S-1 가족 멤버가 진진거 풀이에 진입한다
    Given 사용자가 가족 멤버이고 출제자가 아니다
    And 진진거의 status는 open이다
    When 사용자가 `/quiz/:id/play`에 접근한다
    Then 시스템은 옵션 카드 3장을 셔플해 표시한다
    And 셔플 순서는 사용자 + 진진거 단위로 결정적이다(새로고침해도 동일 순서)
    And 옵션 텍스트만 노출되고 어떤 것이 가짜인지는 표시되지 않는다

  Scenario: S-2 풀이자가 옵션을 고르고 이유를 적는다
    Given 사용자가 `/quiz/:id/play`에 있다
    When 사용자가 옵션 B를 선택하고 이유에 "이건 너무 그럴듯해서 오히려 의심됨"을 적고 "제출"을 누른다
    Then 시스템은 `Answer` 레코드를 생성한다 (`chosenOptionId`, `reasonText`)
    And 사용자에게 "제출됐어요. 결과는 다 풀거나 24시간 뒤에 공개돼요"를 토스트로 표시한다
    And 사용자를 `/home`으로 이동시킨다

  Scenario: S-3 풀이자가 이유 없이 옵션만 고른다
    Given 사용자가 옵션을 선택했지만 이유 입력란을 비웠다
    When 사용자가 "제출"을 누른다
    Then 시스템은 `Answer.reasonText = null`로 저장하고 정상 제출한다

  Scenario: S-4 풀이자가 같은 진진거를 다시 푼다
    Given 사용자가 이미 이 진진거에 답안을 제출했다
    When 사용자가 다시 `/quiz/:id/play`에 접근한다
    Then 시스템은 풀이 화면 대신 "이미 풀었어요. 결과는 [공개 예정 시각]에 공개돼요" 화면을 보여준다
    And 사용자가 옵션 변경/재제출을 시도하더라도 시스템은 거부한다

  Scenario: S-5 출제자가 자기 진진거를 풀려고 한다 (F3 R-11)
    Given 사용자가 진진거의 출제자이다
    When 사용자가 `/quiz/:id/play`에 접근한다
    Then 시스템은 풀이 UI 대신 "내 진진거는 풀 수 없어요. 가족 풀이를 기다리거나 직접 결과를 공개할 수 있어요" 화면을 보여준다
    And [지금 결과 공개] 버튼을 노출한다(F3 R-9)

  Scenario: S-6 가족 전원이 풀이를 마치면 즉시 결과 공개
    Given 진진거가 open 상태이고 풀이 가능 멤버가 N명이다
    And 그 중 N-1명이 이미 답안을 제출했고 1명만 남아 있다
    When 마지막 풀이자가 답안을 제출한다
    Then 시스템은 진진거의 status를 revealed로 전환한다(F3 R-8)
    And `revealedAt = now`
    And 시스템은 직후 AI 자동 코멘트 생성을 비동기로 시작한다(아래 S-10 참조)

Feature: 결과 공개 화면

  Scenario: S-7 결과 화면 진입 — 행복 경로
    Given 진진거가 revealed 상태이다
    And AI 자동 코멘트 생성이 완료됐다
    When 가족 멤버가 `/quiz/:id/result`에 진입한다
    Then 시스템은 다음을 표시한다
      | 섹션 | 내용 |
      | 헤더 | 출제자 닉네임, dayLabel, "진짜 2 / 가짜 1" 라벨 |
      | 옵션 | 옵션 3개. 진짜는 ✅, 가짜는 ❌로 명확히 표기 |
      | 풀이자 결과 | 풀이자별 선택 + 한 줄 이유 + 맞춤/틀림 표시 |
      | 통계 | 속임률, 정답률, "가장 많이 속은 사람" |
      | AI 코멘트 | 결과를 읽기 좋게 한 단락으로 요약/해설 |
      | 액션 | [남의 집 진진거에 공유하기] [가족 대시보드 보기] [댓글 달기] |

  Scenario: S-8 결과 화면 진입 — AI 코멘트 아직 생성 중
    Given 결과는 revealed 상태이지만 AI 코멘트는 아직 미완료다
    When 사용자가 `/quiz/:id/result`에 진입한다
    Then 시스템은 결과 본문을 즉시 표시한다
    And AI 코멘트 영역은 스켈레톤("AI가 결과 코멘트를 쓰고 있어요")으로 표시한다
    And 코멘트가 도착하면 클라이언트가 자동으로 채운다(폴링 또는 SSE)

  Scenario: S-9 결과 화면 진입 — 풀이를 안 한 멤버가 진입
    Given 가족 멤버 중 한 명이 풀이를 한 번도 시도하지 않았다
    And 진진거가 revealed로 전환됐다
    When 그 멤버가 `/quiz/:id/result`에 진입한다
    Then 시스템은 "풀이는 끝났지만 결과를 같이 봐요" 안내를 상단에 표시한다
    And 풀이자별 결과 섹션에서 본인은 "참여 안 함"으로 표시된다
    And 본인 정답률 계산에는 포함되지 않는다

Feature: AI 자동 코멘트

  Scenario: S-10 결과 공개 시 AI 코멘트가 자동 생성된다
    Given 진진거가 revealed로 전환됐다
    When 시스템이 reveal 후 작업 큐에서 코멘트 생성을 처리한다
    Then 시스템은 LLM에 다음 컨텍스트를 전달한다
      | 항목 | 값 |
      | 진짜 옵션 | 텍스트 2개 |
      | 가짜 옵션 | 텍스트 1개, 난이도 |
      | 풀이자별 결과 | 닉네임, 선택, 이유, 맞춤/틀림 |
      | 가족 톤 | (옵션) 최근 진진거 코멘트 통계 |
    And LLM 응답을 1단락(80~200자)의 한국어 코멘트로 받아 `Comment(kind=ai)`로 저장한다
    And `LLMUsage`에 kind=`comment`로 기록한다

  Scenario: S-11 AI 코멘트 톤 가드
    Given LLM 응답이 비방/조롱/혐오/외모 비하 등 금지 패턴을 포함한다
    When 후처리 필터가 패턴을 검출한다
    Then 시스템은 응답을 폐기하고 1회 재호출한다
    And 두 번째 시도도 실패하면 정적 fallback 코멘트를 사용한다 (예: "오늘도 가족이 한 발씩 더 가까워졌어요.")
    And 로그에 차단 이유를 기록한다

  Scenario: S-12 AI 코멘트 생성 실패
    Given LLM 호출이 5xx로 실패했다
    When 시스템이 백오프 재시도(최대 2회)를 마쳤다
    Then 정적 fallback 코멘트를 저장한다
    And 결과 화면에는 정상적으로 코멘트 영역이 채워진다(사용자 영향 최소)

Feature: 결과 공개 후 동선

  Scenario: S-13 결과 화면에서 공개 게시판 공유 진입
    Given 사용자가 출제자이다
    And 결과 화면을 보고 있다
    When 사용자가 [남의 집 진진거에 공유하기]를 누른다
    Then 시스템은 F7(public-board) 공유 위저드의 1단계(익명화 미리보기)로 이동시킨다

  Scenario: S-14 결과 화면 진입은 누구에게나 허용된다(가족 멤버 한정)
    Given 사용자는 진진거가 속한 가족의 멤버이다
    Then 사용자는 진진거 status가 open이든 revealed든 `/quiz/:id/result`를 열 수 있다
    But open 상태라면 결과 본문(정답·풀이자 선택)은 가려지고 "아직 결과가 공개되지 않았어요. 풀이하러 가기"만 보인다
```

## Acceptance criteria

| ID | 검증 |
|----|------|
| S-1, S-2, S-3 | 풀이 제출 E2E + DB 검증. |
| S-4 | 중복 제출 시 409 응답 통합 테스트. |
| S-5 | 출제자 가드 통합 테스트. |
| S-6 | reveal 트리거(전원 풀이) 통합 테스트(F3 R-8와 공유). |
| S-7 | 결과 화면 컴포넌트 스냅샷/E2E. |
| S-8 | AI 코멘트 폴링/스트리밍 E2E. |
| S-9 | 비참여자 결과 화면 노출 E2E. |
| S-10 | LLM 호출 모킹 + Comment 저장 통합 테스트. |
| S-11 | 후처리 필터 단위 테스트. |
| S-12 | LLM 실패 시 fallback 코멘트 통합 테스트. |
| S-13 | 공개 게시판 위저드로 라우팅되는지 E2E(F7와 공유). |
| S-14 | open 상태에서 결과 본문 마스킹 E2E. |

- AI 자동 코멘트는 진진거 1건당 1회만 생성한다(중복 방지를 위한 unique 제약).
- 풀이 제출은 사용자 × 진진거에 대해 한 번만 허용한다(unique constraint).

## Failure modes and recovery

| 실패 | 응답 | 사용자 메시지 |
|------|------|---------------|
| 옵션 없는 진진거(데이터 손상) | 500 + 운영 알림 | "잠시 후 다시 시도해 주세요" |
| 가족 외 사용자가 결과 화면 접근 | 403 | "이 진진거는 다른 가족의 콘텐츠예요" |
| AI 코멘트 영구 실패 | 정적 fallback 텍스트 | (사용자에게는 정상 보임) |
| 풀이 트랜잭션 충돌 | 409 + 1회 자동 재시도 | (사용자 노출 X) |

## Open questions
- OQ-A1: 결과 공개 후 출제자가 풀이자 선택 이유를 보고 후속 질문을 남기는 "회차 마무리" 동선을 두면 더 좋은가(질문왕 랭킹과 연동).
- OQ-A2: AI 코멘트를 풀이자별로 다 다르게 만들 것인지(개인화 vs 비용).
- OQ-A3: 결과 공개 직후 자동으로 게시판 공유 모달을 한 번 띄울 것인가(전환율 vs 거부감).
- OQ-A4: 풀이 시간 측정(누가 가장 빨리 풀었나)을 별도 통계로 노출할 것인가(F6와 연계).
