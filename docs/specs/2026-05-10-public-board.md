## Goal
- 가족 안에서 결과 공개된 진진거 중 재밌거나 따뜻한 것을 출제자가 명시적으로 동의해 익명화된 형태로 전체 게시판에 올리고, 다른 사용자들이 정답을 추리하고 업보트로 반응할 수 있게 한다.

## In scope
- 결과 화면에서 게시판 공유 위저드 진입.
- AI 익명화 (이름·회사·학교·정확한 위치·전화/주소 등 식별자 자동 제거 제안).
- 사용자 익명화 결과 직접 수정.
- 공유 동의 명시 + 게시.
- 게시판 리스트(`/board`) — 오늘의 레전드, 그럴듯, 따뜻함 등 카테고리.
- 게시판 상세(`/board/:id`) — "정답 보기" 가림 동작, 업보트, 댓글.
- 본인 게시물 삭제(48시간 이내).
- 공개 게시판 5종 랭킹.

## Out of scope
- 신고·차단·관리자 페이지(MVP는 신고 폼만 수신, 처리 정책은 v1.1).
- 비로그인 업보트(MVP는 로그인 필수).
- 다른 가족과 직접 채팅.
- 게시물 수정(삭제 후 재공유만 가능).

## User story
- As a 출제자
- I want 우리 가족이 즐긴 진진거 중 정말 재밌는 걸 안전하게 익명화해서 다른 사람들에게 보여주고 싶다
- so that 우리 가족 안에서만 끝나기 아까운 한 컷이 더 많은 사람의 웃음으로 이어진다.

## Definitions
- **공개 게시물(PublicPost)**: 진진거 1건이 익명화되어 게시판에 게시된 단위. 한 진진거당 최대 1건의 PublicPost.
- **익명화 미리보기(Anonymized preview)**: AI가 생성한 변환 결과를 사용자가 검토·수정하는 화면.
- **공개 카테고리(Public category)**: 사용자가 게시 시점에 선택하는 라벨. {`레전드`, `그럴듯`, `가족다운`, `웃긴오답`, `따뜻한`} 중 하나(MVP는 1개 선택).
- **업보트(Upvote)**: 로그인한 사용자가 한 PublicPost에 1번만 줄 수 있는 추천. 토글 가능.
- **노출 가중치(Display rank)**: 리스트 정렬 점수 = upvote_count × decay(time).

## Scenarios

```gherkin
Feature: 결과 화면에서 공유 위저드 진입

  Scenario: S-1 출제자가 결과 화면에서 게시판 공유를 시작한다
    Given 진진거가 revealed 상태이다
    And 사용자가 진진거의 출제자이다
    When 사용자가 [남의 집 진진거에 공유하기]를 누른다
    Then 시스템은 공유 위저드 1단계(익명화 미리보기)로 이동한다
    And LLM에 익명화 요청을 보낸다 (kind=anonymize)

  Scenario: S-2 출제자가 아닌 가족 멤버는 공유할 수 없다
    Given 사용자가 출제자가 아닌 가족 멤버이다
    Then 결과 화면의 [공유하기] 버튼은 보이지 않거나 비활성화된 상태이다
    And 백엔드도 해당 진진거 공유 API에 출제자만 허용한다

Feature: AI 익명화 미리보기

  Scenario: S-3 익명화 결과 미리보기와 직접 수정
    Given 위저드 1단계에 진입했다
    And LLM이 익명화 결과를 응답했다
    Then 시스템은 다음을 화면에 노출한다
      | 영역 | 내용 |
      | 원본 (가족 안에서만 보였던) | 옵션 3개 원문 |
      | 익명화 결과 | AI가 변환한 옵션 3개 |
      | 변경 흔적 | 어떤 단어가 어떻게 바뀌었는지 줄 단위 highlight |
    And 사용자는 익명화 결과를 textarea에서 자유롭게 수정할 수 있다
    And 사용자가 옵션 1개라도 빈 값으로 두면 [다음] 버튼은 비활성화된다

  Scenario: S-4 익명화 규칙
    Given 원문 옵션에 "강남역 스타벅스에서 김민수 팀장한테 칭찬받았다"가 있다
    When 시스템이 익명화한다
    Then 결과는 다음 규칙으로 변환된다
      | 식별자 | 변환 |
      | 사람 이름 | 역할/관계로 ("김민수 팀장" → "팀장") |
      | 정확한 위치 | 도시/동네 단위로 ("강남역 스타벅스" → "카페") |
      | 회사·학교 | 일반화 ("XX회사" → "회사") |
      | 전화·주소·계좌 | 완전 제거 |
      | 가족 닉네임 | 역할로 ("민수" → "가족 한 명", "엄마/아빠/형/누나/언니/오빠/동생/할머니/할아버지"는 유지) |

  Scenario: S-5 안전 가드 — 자극적 내용
    Given 원문이 명백한 폭력/혐오/자해/타인 비방을 포함한다
    When 시스템이 안전 검사기를 통과시킨다
    Then 시스템은 위저드 진입을 거부한다
    And "이 진진거는 안전 가이드라인에 따라 게시판에 공유할 수 없어요" 안내를 표시한다

  Scenario: S-6 익명화 LLM 실패
    Given LLM 호출이 실패했다
    Then 시스템은 1회 자동 재시도 후 실패하면 "AI 익명화에 실패했어요. 직접 익명 버전을 적어주세요" 안내를 표시한다
    And 사용자가 빈 textarea에 직접 익명 옵션 3개를 작성해 진행할 수 있다

Feature: 공유 확정

  Scenario: S-7 공유 동의 + 카테고리 선택 + 게시
    Given 사용자가 위저드 2단계(검토)에 있다
    And 익명화 결과 옵션 3개가 모두 채워져 있다
    When 사용자가 카테고리("레전드")와 게시 동의 체크박스("이 내용은 누구에게나 공개됩니다")를 모두 선택하고 [공유하기]를 누른다
    Then 시스템은 PublicPost를 생성한다 (sourceQuizId, anonymizedTitle, anonymizedOptions, category, authorFamilyHash)
    And `authorFamilyHash`는 가족 단위 해시(가족 식별 가능, 사용자 개인 식별 불가)로 저장된다
    And 가족이 다른 가족이라는 사실 외에는 어떤 가족인지 노출되지 않는다
    And 사용자를 `/board/:postId`로 이동시킨다

  Scenario: S-8 동의 미체크
    Given 사용자가 동의 체크박스를 선택하지 않았다
    When 사용자가 [공유하기]를 누른다
    Then 버튼은 동작하지 않는다
    And 동의 체크박스 옆에 "공유하려면 동의가 필요해요"가 표시된다

  Scenario: S-9 같은 진진거 중복 공유 방지
    Given 같은 진진거가 이미 PublicPost로 게시돼 있다
    When 사용자가 다시 공유 시도한다
    Then 시스템은 신규 PublicPost를 생성하지 않고 기존 PublicPost로 이동시킨다

Feature: 게시판 리스트와 상세

  Scenario: S-10 게시판 메인 리스트
    Given 사용자가 `/board`에 진입했다
    Then 시스템은 다음 영역을 노출한다
      | 영역 | 정렬 기준 |
      | 오늘의 레전드 | 최근 24h 업보트 가중치 상위 |
      | 그럴듯 | 속임률 추정 상위(공개 풀이자의 정답률 낮은 순) |
      | 가족다운 | 카테고리 = `가족다운` 최신 |
      | 웃긴 오답 | 카테고리 = `웃긴오답` 최신 |
      | 따뜻한 | 카테고리 = `따뜻한` 최신 |
    And 각 카드에는 익명화된 옵션 3개와 업보트 수, 댓글 수가 노출된다
    But 정답은 가려져 있다("정답 보기" 버튼)

  Scenario: S-11 정답 가림과 풀이
    Given 사용자가 `/board/:postId`에 진입했다
    When 사용자는 옵션 3개를 본다
    Then 처음에는 어떤 옵션이 가짜인지 표시되지 않는다
    When 사용자가 옵션 1개를 선택해 [정답 보기]를 누른다
    Then 시스템은 정답을 표시한다
    And 사용자의 정답 여부를 익명 풀이 기록(PublicSolveAttempt)으로 저장한다(중복 풀이 1회만 카운트)
    And 게시판 통계의 "공개 정답률"이 갱신된다

  Scenario: S-12 업보트
    Given 사용자가 `/board/:postId`에 있다
    When 사용자가 [👍 업보트]를 누른다
    Then 시스템은 Upvote(postId, voterUserId)를 생성한다
    And 같은 사용자가 같은 게시물에 두 번 누르면 토글로 해제된다
    And 업보트 수가 즉시 갱신된다(낙관적 UI)

  Scenario: S-13 게시판 댓글
    Given 사용자가 `/board/:postId`에 있다
    When 사용자가 한 줄 댓글(1~200자)을 제출한다
    Then 시스템은 PublicComment를 생성한다
    And 댓글에는 작성자 닉네임 첫 글자 + 마지막 글자 + ★ 형식의 가명(예: "민★수")이 표시된다(MVP, OQ-P3 참조)
    But 출제자 본인 댓글은 "🏠 출제자"로 표시된다(누구인지는 가리되 "출제자"라는 사실은 표시)

Feature: 본인 삭제

  Scenario: S-14 출제자 본인이 게시물을 삭제한다
    Given 사용자가 게시물의 출제자이고 게시 후 48시간 이내이다
    When 사용자가 [삭제] 버튼을 누른다
    Then 시스템은 PublicPost.status를 `removed`로 마킹하고 본문을 즉시 가린다
    And 댓글·업보트 데이터는 보존하되 다른 사용자에게는 노출되지 않는다

  Scenario: S-15 48시간이 지난 게시물 삭제
    Given 사용자가 출제자이지만 게시 후 48시간을 넘었다
    When 사용자가 [삭제]를 시도한다
    Then 시스템은 신고 폼을 통한 운영팀 요청 안내로 라우팅한다(MVP)

Feature: 신고

  Scenario: S-16 다른 사용자가 게시물을 신고한다
    Given 로그인한 사용자가 `/board/:postId`에 있다
    When 사용자가 [⚠ 신고]를 누르고 사유 1개를 선택한다
    Then 시스템은 Report 레코드를 생성한다(MVP는 수신만)
    And 사용자에게 "신고가 접수됐어요. 확인까지 시간이 걸릴 수 있어요"를 표시한다
```

## Acceptance criteria

| ID | 검증 |
|----|------|
| S-1, S-2 | 출제자만 공유 진입 가능 E2E. |
| S-3 | 위저드 컴포넌트 + LLM 모킹. |
| S-4 | 익명화 규칙 단위 테스트(케이스 매트릭스). |
| S-5 | 안전 검사기 통합 테스트. |
| S-6 | LLM 실패 fallback E2E. |
| S-7 | DB에 PublicPost + authorFamilyHash 저장 검증. |
| S-9 | 같은 quizId 중복 공유 거부 통합 테스트. |
| S-10 | 5종 섹션 정렬 SQL 쿼리 검증. |
| S-11 | 정답 가림·해제 컴포넌트 + PublicSolveAttempt 저장 검증. |
| S-12 | 업보트 토글 통합 테스트. |
| S-13 | 가명 변환 로직 단위 테스트. |
| S-14, S-15 | 시간 모킹으로 48h 경계 검증. |
| S-16 | Report 수신 통합 테스트. |

- 익명화는 LLM 호출 1회/PublicPost. 호출 카운트는 `LLMUsage` kind=`anonymize`로 기록.
- PublicPost는 `sourceQuizId UNIQUE`로 중복 방지.
- 게시판은 비로그인도 read-only로 열람 가능. 단 풀이/업보트/댓글은 로그인 필요.

## Public board ranking (5종)

| 랭킹 | 산식 |
|------|------|
| 오늘의 레전드 | 최근 24h 동안 업보트 수 (decay 가중) 상위 |
| 가장 그럴듯한 거짓말 | 공개 풀이자의 오답률 상위(min 풀이자 ≥ 20) |
| 가장 가족다운 진진거 | 카테고리 = `가족다운` 최근 7일 업보트 상위 |
| 가장 웃긴 오답 | 카테고리 = `웃긴오답` 최근 7일 업보트 상위 |
| 가장 따뜻한 진진거 | 카테고리 = `따뜻한` 최근 30일 업보트 상위 |

## Failure modes and recovery

| 실패 | 응답 | 사용자 영향 |
|------|------|-------------|
| LLM 익명화 실패 | 사용자 직접 입력 fallback | 게시 가능 |
| 안전 가드 차단 | 게시 거부 + 안내 | 게시 불가, 가족 안에서만 유지 |
| 업보트 동시성 | 토글 idempotent | 업보트 수 일관 |
| 게시물 삭제 후 캐시 | 삭제 즉시 캐시 무효화 | 직후 진입 시 "삭제된 게시물" 표시 |
| 신고 폭주 | 자동 비공개 미적용(MVP) | 운영팀 수동 처리 |

## Open questions
- OQ-P1: 익명화 "가족 닉네임 → 역할" 매핑이 가족마다 다른 호칭(예: "쮸니", "곰돌이")을 못 잡을 수 있다. 가족이 사전 매핑을 입력하는 화면이 필요한가.
- OQ-P2: 게시판 카테고리를 출제자가 선택 vs AI가 추천 vs 둘 다.
- OQ-P3: 댓글 가명 표기 방식. "민★수"가 아닌 동물 닉네임 풀 사용 가능성.
- OQ-P4: 로그인 사용자만 업보트 가능 vs 비로그인도 1회 가능(IP/디바이스 키). 바이럴 vs 어뷰징.
- OQ-P5: "신고 N건 자동 비공개" 임계치(MVP는 수동, v1.1에서 자동화).
- OQ-P6: 게시판에서 가족 단톡방으로 다시 확산되는 외부 공유(OG 미리보기, 카톡/X 공유 버튼)의 범위.
