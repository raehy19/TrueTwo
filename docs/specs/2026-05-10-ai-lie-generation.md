## Goal
- 사용자가 진짜 일 2개를 입력하면 AI가 가족이 헷갈릴 만한 가짜 3개를 즉시 제안하고, 사용자가 그 중 하나를 골라 직접 다듬어 "사람의 손길이 들어간 가짜"로 등록할 수 있게 한다.

## In scope
- `/quiz/new` 위저드 3단계: ① 진짜 2개 입력 ② AI 가짜 후보 3안 ③ 다듬기/난이도/등록.
- 가짜 후보 리롤(최대 2회).
- 가짜 직접 수정(자유 입력).
- 난이도 4단계.
- AI 호출 비용 가드(가족당 진진거 1건 = 최대 3회 호출).
- 안전 가드(LLM이 부적절한 콘텐츠를 만들지 못하도록 시스템 프롬프트와 후처리 필터).

## Out of scope
- AI 결과 코멘트(F5에서 정의).
- 익명화(F7에서 정의).
- 진진거 본문 다국어.
- 음성/사진 진진거.
- AI가 진짜 2개를 자동으로 만들기(MVP는 사람 입력만).

## User story
- As a 출제자
- I want AI가 가족이 속을 만한 그럴듯한 가짜를 제안해 주고, 내가 그 중 하나를 골라 살짝 다듬어 등록하고 싶다
- so that 매일 진진거를 떠올리는 부담 없이도 가족이 즐길 콘텐츠를 만들 수 있다.

## Definitions
- **진짜 옵션(True option)**: 사용자가 입력한 실제 사건. 한 진진거당 정확히 2개.
- **가짜 옵션(False option)**: AI 또는 사용자가 만든 허구 사건. 한 진진거당 정확히 1개.
- **후보(Candidate)**: AI가 한 번의 호출에서 제안한 가짜 텍스트 1건. 한 호출당 3개 후보 반환.
- **리롤(Reroll)**: 후보가 마음에 들지 않을 때 새 후보를 다시 받아오는 동작.
- **난이도(Difficulty)**: 1~4. AI 프롬프트와 가족 풀이 시 표시 라벨에 영향.
- **편집 흔적(Edited)**: 사용자가 AI가 만든 텍스트를 수정한 경우 `QuizOption.edited = true`.

## Difficulty levels

| 값 | 라벨 | 프롬프트 톤 |
|---|------|-------------|
| 1 | 🟢 너무 티 남 | 명백히 사실과 다른 우스꽝스러운 거짓 |
| 2 | 🟡 가족이면 헷갈림 | 평범한 일상 결의 거짓, 진짜와 톤 일치 |
| 3 | 🔴 엄마도 속음 | 진짜 2개의 디테일을 차용한 정교한 거짓 |
| 4 | ⚫ 우리집 레전드급 | 진짜 2개의 인물·장소·습관을 교차 활용한 그럴듯한 거짓 |

기본값: 2 (가족이면 헷갈림).

## Scenarios

```gherkin
Feature: AI 가짜 생성 위저드

  Scenario: S-1 행복 경로 — 진짜 2개 입력 → AI 후보 → 선택 → 다듬기 → 등록
    Given 사용자가 `/quiz/new` 1단계에 있다
    When 사용자가 "진짜 1"에 "오늘 회의에서 칭찬받았다"를 입력한다
    And "진짜 2"에 "점심을 못 먹고 커피만 마셨다"를 입력한다
    And "다음" 버튼을 누른다
    Then 시스템은 LLM에 가짜 후보 3개를 요청한다
    And 응답이 도착하면 2단계 화면에 후보 3개를 카드로 표시한다
    When 사용자가 "퇴근길에 초등학교 친구를 만났다"를 선택한다
    And "다음"을 누른다
    Then 3단계에서 같은 텍스트가 편집 가능한 textarea에 채워진다
    When 사용자가 "퇴근길에 우연히 초등학교 친구를 만나서 30분 수다 떨었다"로 수정한다
    And 난이도를 "🔴 엄마도 속음"으로 선택한다
    And "등록"을 누른다
    Then 시스템은 진진거를 생성하고(F3 R-5 적용) `/home`으로 이동시킨다
    And `QuizOption.edited = true`로 저장한다

  Scenario: S-2 후보가 마음에 안 들면 리롤한다
    Given 사용자가 2단계에서 후보 3개를 보고 있다
    And 이번 진진거에서 사용한 LLM 호출은 1회이다
    When 사용자가 "다른 후보 보기"를 누른다
    Then 시스템은 LLM에 새로운 후보 3개를 요청한다
    And 호출 카운터를 2로 증가시킨다
    And 응답이 도착하면 새 후보 3개로 화면을 교체한다
    And "다른 후보 보기" 버튼은 1회 더 사용 가능 상태로 남아 있다

  Scenario: S-3 리롤 한도 도달
    Given 사용자가 같은 진진거에서 LLM 호출을 이미 3회 사용했다
    Then "다른 후보 보기" 버튼은 비활성 상태이다
    And 버튼 옆에 "오늘 진진거에서 사용 가능한 횟수를 다 썼어요"가 표시된다

  Scenario: S-4 진짜 입력이 너무 짧다
    Given 사용자가 1단계에 있다
    When 사용자가 "진짜 1"에 "응"을 입력하고 "다음"을 누른다
    Then "다음" 버튼은 비활성 상태이다
    And 입력란 아래 "5자 이상 적어주세요"가 표시된다

  Scenario: S-5 진짜 입력이 너무 길다
    Given 사용자가 1단계에 있다
    When 사용자가 "진짜 1"에 201자를 입력한다
    Then 입력란 글자 수 카운터가 빨갛게 표시된다
    And "다음" 버튼은 비활성 상태이다

  Scenario: S-6 사용자가 직접 가짜를 적는다 (AI 우회)
    Given 사용자가 2단계에서 후보를 본다
    When 사용자가 "직접 적기" 토글을 누른다
    Then 후보 카드 아래 빈 textarea가 등장한다
    When 사용자가 자유 입력으로 가짜를 적고 "다음"을 누른다
    Then 시스템은 LLM 호출을 추가로 발생시키지 않는다
    And 3단계에서 사용자가 적은 텍스트가 그대로 채워지고 `QuizOption.edited = true`이다
    And `QuizOption.sourceLLM = null`이다

  Scenario: S-7 난이도가 다음 LLM 호출 프롬프트에 반영된다
    Given 사용자가 2단계에서 후보 3개를 보고 있다
    And 사용자가 화면 상단 난이도 토글을 "⚫ 우리집 레전드급"으로 바꾼다
    When 사용자가 "다른 후보 보기"를 누른다
    Then 시스템은 새 후보 요청 시 난이도 4 톤을 반영한 시스템 프롬프트로 호출한다

  Scenario: S-8 LLM 응답 지연
    Given 사용자가 1단계 → 2단계로 넘어갔다
    And LLM 응답이 첫 토큰까지 3초가 걸린다
    Then 2단계 진입 즉시 스켈레톤 카드 3장과 진행 메시지("AI가 가짜 후보를 만들고 있어요")를 표시한다
    And 첫 토큰이 도착하면 카드를 점진 렌더링한다
    And 8초 안에 마지막 후보가 도착해야 한다

  Scenario: S-9 LLM 호출 실패
    Given 2단계에서 LLM 호출이 5xx로 실패했다
    Then 시스템은 "AI가 잠깐 졸고 있어요. 가짜를 직접 적거나 다시 시도할 수 있어요"를 표시한다
    And [다시 시도] 버튼은 LLM 호출 카운터를 차감하지 않는다(실패 호출은 무료)
    And [직접 적기] 버튼은 항상 활성화돼 있다(S-6과 동일 경로)

  Scenario: S-10 안전 가드 — 사용자 진짜 입력에 민감 토픽이 들어 있다
    Given 사용자가 진짜 입력에 민감 표현(자해/혐오/타인 식별 정보 등 차단 카테고리)을 포함했다
    When 사용자가 "다음"을 누른다
    Then 시스템은 LLM 호출 전에 입력을 검출하고 안내 모달을 띄운다
    And "이 내용은 가족 전원에게 보입니다. 그래도 진행하시겠어요?" 확인을 받는다
    And 사용자가 확인하면 LLM 호출을 진행하되 시스템 프롬프트에 "가짜는 본인이 적은 민감 주제를 강화하지 말 것" 규칙을 추가한다
    And 사용자가 취소하면 입력 화면으로 돌아간다

  Scenario: S-11 안전 가드 — LLM 응답이 부적절하다
    Given LLM이 후보 3개 중 1개에 비속어 또는 인물 비방을 포함해 응답했다
    When 시스템 후처리 필터가 차단 패턴을 검출한다
    Then 시스템은 해당 후보를 표시하지 않는다
    And 보이는 후보가 2개 이하라면 자동으로 동일 호출 카운트 안에서 1회 즉시 보충 호출한다(보충 호출은 사용자에게 카운트로 보이지 않음)

  Scenario: S-12 LLM 후보가 진짜 2개 중 하나를 그대로 베꼈다
    Given LLM이 가짜 후보 3개 중 1개를 진짜 옵션 텍스트와 동일/거의 동일하게 응답했다
    When 시스템이 유사도(예: 정규화 후 70% 이상 토큰 일치)를 검출한다
    Then 해당 후보는 표시하지 않는다
    And 부족분은 S-11과 동일하게 보충 호출로 채운다

  Scenario: S-13 사용자가 위저드를 닫는다
    Given 사용자가 2단계 또는 3단계에서 뒤로 가기/닫기를 누른다
    Then 시스템은 입력값을 클라이언트 로컬에 임시 저장한다(F3 R-18)
    And 다음 진입 시 마지막 단계에서 복원된다
    And 임시 저장은 AI 호출 카운터·후보 응답 캐시도 함께 보존한다(다시 호출 안 일어나도록)
```

## Acceptance criteria

- 모든 시나리오는 통합/E2E로 자동 검증 가능해야 한다.
- LLM 호출 카운터는 가족 + 진진거(아직 미발행 임시 키) 단위로 카운트된다. 호출 한도 = 3회(R-11/PRD §9 B-11).
  - 1회: 1단계 → 2단계 진입 시 자동 호출.
  - 2회 / 3회: 사용자 명시적 "다른 후보 보기" 클릭.
  - 보충 호출(S-11/S-12)은 카운터에 포함하지 않음.
- 모든 LLM 호출은 `LLMUsage` 테이블에 (kind=`generate`|`reroll`, model, tokensIn, tokensOut, costKRW)로 기록.
- 가짜 옵션의 `text` 길이는 5~200자.
- 후보 카드 한 개의 텍스트 길이도 5~200자(LLM 후처리 필터에서 강제).
- 위저드 단계 이동 시간(클라이언트 단독 작업)은 200ms 이하.

## LLM Prompt Outline (참고)

```text
[시스템]
너는 한국 가족의 데일리 게임 "진진거"의 가짜 옵션 생성기다.
규칙:
- 결과는 정확히 3개의 한국어 가짜 일상 사건으로만 이루어진 JSON 배열이다.
- 각 항목은 5~120자의 일상 한 줄 사건이며, 진짜 옵션 두 개의 톤·길이·시점과 비슷해야 한다.
- 진짜 옵션의 인물·장소·시간 단서를 자연스럽게 변형해 그럴듯하게 만든다.
- 비속어, 차별, 자해, 폭력, 타인 식별 정보(전화번호/주소/회사명), 정치, 종교 단정 표현 금지.
- 절대 진짜 옵션 텍스트와 동일/거의 동일한 문장을 쓰지 않는다.

[사용자]
난이도: {difficulty_label}
진짜 1: {true_1}
진짜 2: {true_2}
가족 메모(있으면): {family_meta_optional}
가짜 후보 3개를 만들어줘.
```

## Failure modes and recovery

| 실패 | 응답 | 사용자 영향 |
|------|------|-------------|
| LLM 5xx | 사용자에게 재시도/직접 입력 안내. 카운트 차감 X. | 후보 0개 표시. |
| 응답이 JSON 아님 | 1회 자동 재시도 후 실패 시 재시도 안내. | 후보 0개 표시. |
| 응답 후보가 2개 이하(필터링 결과) | 보충 호출로 3개 충족. 카운트 차감 X. | 사용자는 항상 3개를 본다. |
| 위저드 임시 저장 손상 | 1단계부터 다시 시작. 입력 손실 안내. | 1회 입력 재요청. |
| 안전 가드 위반(LLM 응답이 모두 차단) | "다른 표현으로 다시 시도해 주세요" 안내. | 사용자 직접 입력 권장. |

## Open questions

- OQ-G1: 난이도 4("우리집 레전드급")는 시간이 갈수록 가족 컨텍스트(이전 진진거 결과)를 프롬프트에 넣어야 더 효과적이지 않은가? 비용/프라이버시 트레이드오프.
- OQ-G2: 후보 카드를 "한 번 보면 다시 같은 후보가 안 나오게" 캐시할지(가족 전체 / 사용자 단위).
- OQ-G3: 위저드 임시 저장을 서버 측에도 저장할지(다른 기기에서 이어서 작성).
- OQ-G4: 사용자의 평소 톤(이전 등록 텍스트)을 few-shot으로 넣을지. 개인화 vs 비용/프라이버시.
