## Goal
- 한 가족 멤버가 하루 1개 진진거를 등록하고 즉시 가족이 풀 수 있게 만든다. 어제 등록을 놓친 경우 오늘 한 번 더 등록해 전일치를 만들 수 있다.

## In scope
- 일일 등록 한도(서비스 시간대 기준 "하루 1개").
- 백로그 등록 정책(어제 미등록 시 오늘 추가 1개 = 오늘 최대 2개).
- 등록 즉시 풀이 가능하게 하는 발행(publish) 처리.
- 풀이 가능 창(등록 시각으로부터 24시간) 관리.
- 결과 공개 트리거 3종(전원 풀이 / 출제자 공개 / 24시간 경과).
- 출제자 자기 진진거 풀이 금지.
- 등록 중간 저장(임시 저장).

## Out of scope
- 등록된 진진거 본문 수정(공개 게시판 공유 직전 익명화 편집은 별도 spec).
- AI 가짜 생성 자체(F4 spec).
- 풀이 화면 UX(F5 spec).
- 알림/리마인드.

## Definitions
- **서비스 시간대(Service TZ)**: `Asia/Seoul` (UTC+9). 모든 일자 라벨/한도 카운트의 기준.
- **dayLabel**: 진진거가 "어느 날의 진진거"인지를 나타내는 `YYYY-MM-DD`(KST). 등록 시점이 아닌 이 라벨 기준으로 한도가 계산된다.
- **오늘(Today)**: 사용자 등록 트랜잭션 시점의 KST 일자.
- **어제(Yesterday)**: 오늘 - 1일 (KST).
- **publishAt**: 풀이가 가능해지는 시각. = `createdAt`. 즉시 풀이.
- **revealAt**: 시스템이 자동으로 결과를 공개하는 시각. = `publishAt + 24h`.
- **revealedAt**: 실제로 결과가 공개된 시각. 가장 빠른 트리거가 결정한다.
- **백로그 진진거(Backlog quiz)**: `dayLabel = yesterday(KST)`이고 `isBacklog = true`로 등록된 진진거. 동일 사용자 동일 가족 안에서만 1개 허용.
- **출제자(Author)**: 진진거의 등록 사용자.

## Requirements (EARS)

### 등록 한도

- **R-1 (Ubiquitous)**: 시스템은 한 사용자가 같은 `familyId` 안에서 같은 `dayLabel`로 등록한 진진거를 최대 1개로 제한한다.

- **R-2 (Event-driven)**: 사용자가 진진거 등록을 요청할 때, 시스템은 다음 두 가지를 모두 확인한 뒤에만 새 진진거를 생성한다.
  - (a) 오늘 dayLabel로 사용자가 등록한 진진거가 0개여야 한다(R-1).
  - (b) 백로그 등록 요청인 경우, 어제 dayLabel로 사용자가 등록한 진진거가 0개여야 한다.

- **R-3 (State-driven)**: 백로그 등록 가능 상태는 다음을 모두 만족할 때만 참이다.
  - 어제 dayLabel(KST)로 사용자의 진진거가 존재하지 않는다.
  - 사용자가 오늘 이미 백로그 진진거를 등록하지 않았다.
  - 즉, 같은 KST일 안에서 한 사용자가 등록할 수 있는 최대 진진거 수는 2개이다(오늘 1 + 어제 백로그 1).

- **R-4 (Unwanted)**: 만약 사용자가 R-1 또는 R-2를 위반하는 등록을 시도하면, 시스템은 등록을 거부하고 원인을 명시한다.
  - "오늘은 이미 진진거를 등록했어요. 내일 다시 등록할 수 있어요."
  - "어제 진진거가 이미 있어서 백로그 등록을 추가로 할 수 없어요."

### 발행과 풀이 가능 창

- **R-5 (Event-driven)**: 사용자가 등록을 완료할 때, 시스템은 진진거의 `publishAt = now()`, `revealAt = now() + 24h`로 즉시 발행한다.

- **R-6 (Ubiquitous)**: 시스템은 풀이 가능 상태(`status = open`)인 동안 가족 멤버(출제자 제외)에게 풀이 진입을 허용한다.

- **R-7 (Event-driven)**: 시간이 `revealAt`에 도달하면, 시스템은 진진거의 `status`를 `revealed`로 전환하고 `revealedAt`을 현재 시각으로 기록한다.

- **R-8 (Event-driven)**: 가족 멤버 중 출제자를 제외한 전원이 풀이를 마치면, 시스템은 즉시 진진거의 `status`를 `revealed`로 전환하고 `revealedAt`을 현재 시각으로 기록한다.

- **R-9 (Event-driven)**: 출제자가 "지금 결과 공개" 버튼을 누르면, 시스템은 진진거의 `status`를 `revealed`로 전환하고 `revealedAt`을 현재 시각으로 기록한다. 이미 풀이를 마친 멤버의 답안은 그대로 유지된다.

- **R-10 (State-driven)**: 진진거가 `status = revealed`인 동안에는 새로운 풀이가 추가되지 않는다. 단, 결과 화면에서 "정답 보기"는 가족 모든 멤버에게 허용된다.

### 출제자 제약

- **R-11 (Unwanted)**: 만약 출제자가 자신의 진진거를 풀이(answer 제출)하려 시도하면, 시스템은 요청을 거부한다.

- **R-12 (Optional feature)**: 출제자가 "출제 직후 1분" 동안 자기 입력 본문을 수정하는 기능이 활성화된 경우, 시스템은 옵션·이유 텍스트를 수정할 수 있게 허용한다(MVP에서는 비활성, OQ-2 참조).

### 백로그 등록 UX

- **R-13 (Event-driven)**: 사용자가 `/quiz/new`에 진입할 때, 시스템은 백로그 가능 여부(R-3)를 평가해 다음 안내를 노출한다.
  - 가능: "어제 진진거를 안 올렸어요. 어제치 진진거를 먼저 만들 수도 있어요." + [어제치 만들기] / [오늘치 만들기] 토글.
  - 불가능: 토글 없이 오늘치만 노출한다.

- **R-14 (Event-driven)**: 사용자가 "어제치 만들기"를 선택해 등록을 완료한 경우, 시스템은 `dayLabel = yesterday(KST)`, `isBacklog = true`로 진진거를 생성한다.

- **R-15 (Ubiquitous)**: 백로그로 등록된 진진거의 `publishAt`도 즉시(now)로 설정된다. dayLabel만 어제로 표기될 뿐, 풀이 가능 창은 동일한 24시간이다.

### 일자/타임존 처리

- **R-16 (Ubiquitous)**: 모든 일자 비교(`today`, `yesterday`)는 `Asia/Seoul` 자정 기준으로 계산된다.

- **R-17 (Ubiquitous)**: `dayLabel`은 사용자 입력이 시작되는 시각이 아니라 **등록 트랜잭션이 commit되는 시각**의 KST 일자를 사용한다(R-14의 백로그 케이스만 yesterday로 강제).

### 임시 저장

- **R-18 (Optional feature)**: `/quiz/new` 위저드는 단계 이동 시 클라이언트 로컬에 임시 저장한다. 사용자가 같은 기기로 다시 진입하면 마지막 단계로 복원된다.

- **R-19 (Ubiquitous)**: 시스템은 미발행 임시 저장본을 절대 가족에게 노출하지 않는다.

### 동시성

- **R-20 (Ubiquitous)**: 등록 트랜잭션은 직렬화 가능 격리 수준 또는 동등한 잠금으로 R-1/R-3을 보장한다(같은 사용자가 빠르게 두 번 누르더라도 두 개가 동시에 생성되지 않는다).

## Acceptance criteria

| ID | 검증 |
|----|------|
| R-1 | 같은 사용자가 같은 dayLabel로 두 번째 등록을 보내면 409 응답. 통합 테스트. |
| R-2 | 백로그 + 오늘 분기 두 가지 모두 통합 테스트. |
| R-3 | 어제·오늘 진진거 존재 매트릭스(0/0, 1/0, 0/1, 1/1)에 대한 4가지 케이스 단위 테스트. |
| R-4 | 거부 사유 메시지 텍스트가 사용자 화면에 정확히 노출되는지 E2E. |
| R-5 | 등록 직후 발행 상태(`status = open`, `publishAt`, `revealAt` 정확성) DB 검증. |
| R-7 | 시간 모킹으로 24h 경과 시 자동 reveal 트리거 검증. |
| R-8 | 가족 N-1명이 풀이 마치면 즉시 reveal 되는지 E2E. |
| R-9 | 출제자 "지금 공개" 버튼 동작 E2E. |
| R-11 | 출제자가 본인 진진거 answer API 호출 시 403. |
| R-13 | 어제치 진진거 없는 사용자가 `/quiz/new` 진입 시 토글 노출 E2E. |
| R-15 | 백로그 진진거의 풀이 가능 창이 등록 + 24h인지 검증. |
| R-16, R-17 | KST 자정 직전 등록 케이스 단위 테스트(예: 등록 트랜잭션이 23:59:59에 시작해 00:00:01에 commit되는 경우). |
| R-20 | 동일 사용자 두 요청 race condition 테스트. |

## Failure modes and recovery

| 실패 | 시스템 응답 | 사용자 메시지 |
|------|-------------|---------------|
| 한도 초과 | 409 | "오늘은 이미 진진거를 등록했어요." |
| 백로그 한도 초과 | 409 | "어제치 진진거가 이미 있어요." |
| 가족에 속하지 않음 | 403 | "먼저 가족에 가입해야 진진거를 등록할 수 있어요." |
| AI 가짜 생성 실패 → 직접 입력 fallback | 200 (옵션 텍스트만) | "AI가 잠깐 졸고 있어요. 직접 가짜를 적어볼까요?" |
| 트랜잭션 충돌 | 409 + 클라이언트 1회 재시도 | 사용자에게 노출 안 함 |

## Examples

```text
오늘 = 2026-05-10 (KST)
어제 = 2026-05-09 (KST)

Case A: 사용자 A가 어제도 안 올림, 오늘도 처음 진입
  /quiz/new → "어제치 만들기" / "오늘치 만들기" 토글 표시
  "어제치 만들기" 선택 후 등록 → dayLabel=2026-05-09, isBacklog=true
  바로 다시 /quiz/new → 토글 사라짐, 오늘치만 등록 가능 → dayLabel=2026-05-10
  세 번째 시도 → R-4로 거부

Case B: 사용자 A가 어제 등록함, 오늘 첫 등록
  /quiz/new → 토글 없음, 오늘치만 표시 → dayLabel=2026-05-10
  두 번째 시도 → R-4로 거부

Case C: 사용자 A가 23:59:30에 진진거 등록 시작, commit이 00:00:05에 발생
  dayLabel = commit 시각 KST = 2026-05-11
  사용자가 곧이어 /quiz/new 진입 시 → "오늘치"는 이미 등록됨, "어제치(2026-05-10)" 백로그 가능
```

## Open questions

- OQ-Q1: 출제자가 등록 직후 1분 이내에 본문을 수정할 수 있게 할지(R-12). 재미 vs 공정성.
- OQ-Q2: 백로그 등록 가능 일수를 "어제만"이 아니라 "최근 N일"로 늘릴지(현재는 어제 1일만).
- OQ-Q3: 자동 reveal 시(R-7) 풀이를 시작했다가 마치지 못한 사용자의 부분 답안 처리(폐기 vs 마지막 선택 자동 제출).
- OQ-Q4: 가족이 1명뿐일 때(=출제자뿐) 풀이자가 0명. R-8을 어떻게 적용할지(자동 reveal까지 기다리거나 즉시 reveal 옵션).
- OQ-Q5: 여행/오프 모드. 사용자가 "오늘은 등록 못 함"을 미리 표시하면 백로그 권리가 누적되어야 하는가(MVP는 누적 없음).
