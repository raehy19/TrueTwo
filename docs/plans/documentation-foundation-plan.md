# 문서 기반 초기 세팅 계획

## 목적
- 구현 전에 프로젝트 운영 기준을 문서로 고정한다.
- 짧은 세션 반복에도 이어서 작업 가능한 상태를 만든다.
- 불명확한 요구와 확정된 결정을 분리 관리한다.

## 문서 메타
- 작성일: `<YYYY-MM-DD>`
- 프로젝트명: `<project-name>`

## 이번 단계 범위
- 저장소 운영 규칙 정리
- 문서 인덱스와 디렉터리 구조 마련
- 현재 상태 / TODO / 승인 큐 / E2E 체크리스트 생성
- 제품 브리프의 기본 골격 생성

## 이번 단계 비범위
- 애플리케이션 코드 작성
- 기술 스택 확정
- DB 스키마 설계
- API 계약 정의
- UI 설계 상세화

## 산출물
- 루트 README
- 루트 AGENTS
- 문서 운영 맵
- 제품 브리프 초안
- 현재 상태 문서
- 우선순위 TODO 계획
- 승인 대기 큐
- E2E 시나리오 체크리스트

## 작업 순서
1. 빈 저장소 기준선 확인
2. 문서 구조와 역할 정의
3. 운영 문서 작성
4. 제품 정의 미확정 항목을 승인 큐로 이동
5. 이후 세션이 바로 시작할 수 있게 현재 상태 요약 고정

## 완료 기준
- 새 세션이 `docs/README.md`만 읽고도 시작 가능하다.
- 구현 전 필요한 미확정 사항이 승인 큐에 정리돼 있다.
- TODO가 우선순위 기준으로 정리돼 있다.
- E2E 관점의 검토 틀이 존재한다.
- 코드 없이도 프로젝트 진행 방식이 문서로 설명된다.

## 다음 단계 제안
1. 제품 브리프를 실제 문제 정의로 채운다.
2. MVP 범위와 제외 범위를 확정한다.
3. 핵심 사용자 흐름을 E2E 문서로 구체화한다.
4. 그 후에만 아키텍처 초안과 구현 계획으로 이동한다.
